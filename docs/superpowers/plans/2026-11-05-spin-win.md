# Daily Spin & Win implementation

Approved intent: one free spin per verified account per Malaysia calendar day; small MYR vouchers credited automatically to the existing top-up-only rewards ledger, no-prize outcome, and physical prizes recorded for owner fulfilment. Physical probabilities: iPhone 18 Pro 0.001%, PS5 0.002%, Smart TV 0.002% while stock exists. No claim that equal wheel segments have equal probabilities.

Implementation decisions: 100,000 integer draw slots using server secrets.randbelow. Starting voucher distribution RM0.10 6%, RM0.20 2%, RM0.50 1%, RM1 0.7%, RM2 0.25%, RM5 0.05%; remaining slots no prize. Admin-visible defaults, campaign disabled initially, zero physical stock and zero voucher budget until owner configures them. Exhausted stock/budget probability goes to no prize and effective odds retained in the API and admin panel. Freeze a settings version in each award. Daily results are idempotent, serialised with the existing cross-database rewards lock and recorded atomically with voucher credit, stock, admin notifications and audit. Test/real modes isolated.

1. Build spin_win.py API module reusing private platform_config, verified-user/admin guards, rewards ledger, audit and notifications. Include customer history, current state, budget/stock settings and paginated admin physical-winner queue with winner account ID/name/email and status log. No public PII or shipping-address collection. Verify deterministic outcomes, double requests/concurrency, Malaysia midnight, atomic rollback, stock/budget exhaustion, FX failure, admin authorization, test/real separation and quote redemption scope.
2. Add customer wheel, server-decided animation, clear result/history/bonus links and daily reset. Add admin settings and winner queue, navigation from rewards/admin console and a home entry. User refinement: remove the customer probabilities and how-it-works panels; center the wheel. Keep administrative rules and odds. Responsive/keyboard/reduced-motion support. Use existing select controls.
3. Reuse existing Top Up reward redemption cap rather than altering global economics. Enable reward quotes in current supplier test checkout with exact server SKU/USD prices and verify reduced charge/reservation rollback; retain test-only delivery protections.
4. Run relevant reward/payment/security/JS tests and build; inspect desktop/mobile UI and record screenshots. No production deployment or real campaign activation.
