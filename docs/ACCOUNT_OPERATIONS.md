# Account and marketplace operations

The account page now provides profile preferences, password changes, confirmed email changes, linked sign-in providers, optional Authenticator TOTP, single-use recovery codes, active sessions, device revocation, and the user's block list. MFA is opt-in: implementation does not enroll existing accounts. TOTP secrets use the existing AES-GCM delivery encryption key with account-specific associated data; recovery codes are stored hashed. Keep the encryption key backed up separately. Setup requires the current site password and a real Authenticator code. Enabling or disabling MFA revokes other sessions; password changes revoke every session. OAuth sign-ins must complete the same MFA challenge when enabled. Email changes require confirmation at the new address and notify the old address. No credentials or setup secrets are written to browser storage.

Catalogue readiness is an admin page, not a supplier feed. It reports coverage and incomplete titles, descriptions, product attributes, platform, region, delivery terms, and photos. Production moderation requires structural completeness and an explicit moderator quality confirmation. Human reviewers must still check accuracy and authorization. No real listings, seller identities, reviews or sales are fabricated. SentryLoot remains the product name at gamestorehub.com.

Each new order item records its listing and seller availability at checkout. Later listing edits do not alter this promise. Historic orders are labelled legacy because their original full terms were never stored; deadlines are not invented for them. Delivery deadlines start at payment, respect the seller's timezone and next opening, and remain fixed afterward. Vacation blocks new checkout; ongoing orders continue. Durations are elapsed time from the next opening, not a business-hours stopwatch.

Support requests have an ID, category, optional authorized order, reply history, notifications, and open / waiting-customer / resolved states. Users see their own requests; admins see the support queue. Dispute case pages show the reason, target response window, comments, evidence and moderator decisions. Evidence photos are limited to the uploader and admins, normalized before private R2 storage, and accessed through short-lived signed URLs. Closed-case evidence is removed after 30 days through the existing evidence-retention cron; account deletion also removes uploaded evidence. These response windows are targets, not an automatic promise of a staffed support team. Real settlements remain disabled.

Blocking prevents new conversations, purchases and messages between the pair. The history stays readable. Communication needed for an active paid order or dispute stays available. Bulk edits validate ownership for the entire selection and apply in one transaction; any failure rolls back all changes. Existing moderation and reservation rules still apply.

## Deployment and reminders

Apply `supabase/migrations/20261019200000_account_operations.sql` before serving the new code. Startup additionally marks historic snapshots. New tables have RLS enabled and no browser-role grants. `scripts/audit_supabase.py` checks these tables and columns.

The deadline runner only records in-app reminders and overdue notices, once per order item and kind. It never releases funds, refunds or completes orders. GitHub Actions runs it on a best-effort 15-minute schedule using the existing server-side database secret; delays are possible. The scheduled process creates no web sessions and uses a temporary process-only signing key. Vercel's authenticated daily cron is a fallback compatible with Hobby scheduling. Inspect the GitHub workflow and `/api/admin/operations/cron-runs` for runner results. Payment and Top Up integrations are outside this change.
